# MyTool — مراجعة ما قبل التشغيل الحقيقي

التاريخ: 2026-09-13
الحالة: مفتوحة — نعالج البنود واحدًا واحدًا ونغلق كل بند بعد الاختبار.

## ملاحظات موجودة مسبقًا

- [ ] **#57 — أسعار أول جرد:** التحقق من إضافة إدخال سعر الشراء والبيع عند الجرد عندما يكون المنتج بلا أسعار. الفحص الحالي يؤكد أن شاشة الجرد تطلب الكمية والسبب فقط، لذلك هذه النقطة **غير منفذة بعد**.
- [ ] **#56 — أسعار الفروع الأخرى كمرجع:** عند عدم وجود سعر شراء/بيع للمنتج في الفرع الحالي، يمكن عرض أسعار نفس المنتج في الفروع الأخرى كقيمة استرشادية فقط. لا تُنسخ تلقائيًا ولا تصبح سعر الفرع الحالي إلا بعد اعتماد المستخدم.

## نقاط حرجة قبل التشغيل

- [ ] **A1 — سعر البيع عند تغيير المنتج:** في شاشة البيع قد يبقى سعر المنتج السابق عند تغيير المنتج/الفرع. المطلوب مسح السعر القديم فورًا، ثم تحميل آخر سعر بيع للمنتج الحالي إن وجد، وإلا تبقى الخانة فارغة.

- [ ] **A2 — تصحيح أو إلغاء عملية بيع/شراء خاطئة:** لا يوجد مسار واضح وآمن لـ Void/Cancel. المطلوب عملية عكس موثقة بدل حذف التاريخ، مع السبب وصلاحية الإدارة وتأثير صحيح على المخزون والحسابات.

- [ ] **A3 — فصل المنتج التجريبي عن الحقيقي عند إضافة العامل:** دالة `worker_add_product` تنشئ المنتج حاليًا بالقيمة الافتراضية `is_test=false`. يجب أن يرث المنتج نوع جلسة العامل حتى لا يدخل منتج تجريبي ضمن البيانات الحقيقية.

- [ ] **A4 — حسم الرصيد الافتتاحي:** الرصيد الافتتاحي لمحل دار ومحل سانتفي ما زال `not_started`. يجب اختيار سياسة واحدة قبل الاعتماد الكامل: جرد افتتاحي رسمي وتأكيده، أو توثيق اعتماد الجرد التدريجي الحالي.

- [ ] **A5 — مخزون حقيقي بدون أسعار:** توجد في محل سانتفي منتجات مجرودة ولها كمية لكن بلا سعر شراء/بيع، ومنها كمبيوتر L13 وسماعة بلوتوث Hoco. بعد تنفيذ #57 تُستكمل هذه الأسعار حتى لا يبقى مخزون حقيقي بتكلفة صفر.

## نقاط مهمة بعد الحرجة

- [ ] **A6 — تنظيف منتجات حقيقية بلا حركة:** المنتجات IDs `28` و`29` و`30` أسماؤها تجريبية/عشوائية ولا توجد عليها مشتريات أو مبيعات أو جرد أو تحويلات. تُراجع ثم تُحذف أو تُؤرشف قبل اعتماد البيانات الحقيقية.

- [ ] **A7 — Pagination لشاشة المنتجات:** شاشة المنتجات تعرض القائمة كاملة. المطلوب ترقيم صفحات أو تحميل تدريجي مع بحث، خصوصًا للهاتف.

- [ ] **A8 — اختبار دورة تشغيل كاملة:** الاختبار الآلي الحالي يركز على القالب/الشريط المشترك. نحتاج Smoke/E2E لدورة: منتج → شراء → مخزون → بيع → جرد → تحويل، مع التحقق من الكميات والأسعار وعزل الفروع.

## نتائج مطمئنة من الفحص

- لم يظهر مخزون سالب في **المنتجات الحقيقية** وقت الفحص.
- صلاحيات كمال مرتبطة فعليًا بمحل سانتفي.
- كلمات مرور العمال مخزنة بصيغة bcrypt وليست كنص مباشر.
- RLS مفعّل على جداول التشغيل الرئيسية.
- فحص GitHub الخاص بالقالب نجح على آخر تعديل تم فحصه.

## ترتيب الإصلاح المقترح

1. A1 — سعر البيع عند تغيير المنتج.
2. #57 + A5 — أسعار أول جرد وتنظيف المخزون بلا أسعار.
3. A3 — فصل التجريبي عن الحقيقي عند إضافة المنتج.
4. A2 — تصحيح/إلغاء العمليات الخاطئة.
5. A4 — حسم الرصيد الافتتاحي.
6. #56 — أسعار الفروع الأخرى كمرجع استرشادي.
7. A6 — تنظيف المنتجات 28–30.
8. A8 — اختبار دورة التشغيل الكاملة.
9. A7 — Pagination شاشة المنتجات.

قاعدة العمل: لا نغلق أي بند بمجرد تعديل الكود؛ يُغلق فقط بعد اختبار السلوك فعليًا.
