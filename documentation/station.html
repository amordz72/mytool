Station Connect — من GitHub إلى ONLINE

هذه الصفحة هي الدليل التشغيلي الكامل للكمبيوتر الحقيقي: تنزيل المشروع، الإعداد، الفحص، التشغيل، الاعتماد من MyTool، اختبار ONLINE/OFFLINE، التحديث لاحقًا، واستكشاف الأخطاء.

مطبق الآنServer V1 يعملمودم/USSD لاحقًا

لماذا أنشأنا Station Connect؟

بدأت المشكلة قبل Station Connect: أردنا تجربة Flexy من موقع أونلاين، بينما المودم USB موجود على كمبيوتر Windows داخل المحل. الموقع وحده لا يستطيع الوصول مباشرة إلى هذا المودم المحلي.

Internet Website X لا يصل مباشرة إلى X USB Modem on Windows

الحل الحاسم لم يكن البحث فقط عن استضافة أقوى، بل فصل المسؤوليات:

Online Server ↑ | HTTPS / WebSocket outbound | Windows Agent | v Local USB Modem
القاعدة: السيرفر لا يدخل إلى كمبيوتر المحل. الكمبيوتر نفسه يفتح الاتصال إلى السيرفر، ثم ينفذ العمل محليًا ويرجع النتيجة.

لماذا فصلناه عن MyTool وSupabase؟

حتى لا يصبح برنامج الكمبيوتر مربوطًا بموقع واحد أو Framework واحد. Agent يعرف عقدًا ثابتًا وعنوانًا واحدًا فقط:

SERVER_URL=https://.../station-gateway
Station Agent | | Stable Contract v SERVER_URL ├─ Supabase الآن ├─ Laravel لاحقًا └─ أي Server Provider آخر

إذا تغير السيرفر مستقبلًا نحافظ على Contract ونغير الرابط، بدل إعادة كتابة منطق Windows والمودم.

المرجع الذي يمنعنا من العودة لنفس الدوامة

من الآن لا نعتمد على المحادثة وحدها. نفس المشروع موثق في ثلاث طبقات:

Developerلماذا؟ القرار، أصل المشكلة، السبب، الأخطاء السابقة والقواعد المعمارية.
Project Repositoryماذا يعمل فعلًا؟ الكود، Contract، STATUS، NEXT-STEP وتعليمات التشغيل.
Web Documentationكيف أفهمه وأشغله؟ الخريطة البصرية والخطوات من GitHub حتى ONLINE/OFFLINE.
إذا ضاع السياق لاحقًا: الموقع لا يتصل بالمودم؛ Windows Agent يتصل بالسيرفر Outbound عبر Contract ثابت.

1. تنزيل المشروع من GitHub

المكان المقترح على الكمبيوتر:

C:\MyTool\station-connect

PowerShell أو CMD:

cd C:\MyTool git clone https://github.com/amordz72/station-connect.git cd station-connect\agent
إذا طلب GitHub تسجيل الدخول لأن المستودع Private، أكمل تسجيل الدخول ثم أعد أمر git clone.

2. إعداد Agent

انسخ ملف الإعداد النموذجي إلى .env.

PowerShell

Copy-Item .env.example .env

CMD

copy .env.example .env

القيمة الحالية للسيرفر:

SERVER_URL=https://wqyebqzbbpohbnznqdjj.supabase.co/functions/v1/station-gateway HEARTBEAT_MS=30000 STATUS_MS=30000 REQUEST_TIMEOUT_MS=10000
قاعدة ثابتة: إذا نقلنا السيرفر مستقبلًا نغيّر SERVER_URL فقط، ما دام Contract V1 نفسه محفوظًا.

3. فحص Agent قبل التشغيل

npm run check

النتيجة المطلوبة: ينتهي الفحص بدون Syntax Error.

4. تشغيل Agent

npm start

في أول تشغيل فقط يقوم Agent بهذه الخطوات:

  1. إنشاء Station UUID ثابت.
  2. إنشاء Secret عشوائي.
  3. حماية Secret محليًا بـWindows DPAPI.
  4. قراءة MachineGuid محليًا وتحويله إلى SHA-256 قبل الإرسال.
  5. إرسال Enroll إلى السيرفر.
  6. السيرفر ينشئ الكمبيوتر بحالة PENDING.
لا تغلق نافذة Agent أثناء الاختبار الأول.

5. اعتماد الكمبيوتر من MyTool

افتح شاشة المحطات:

https://amordz72.github.io/mytool/access-admin/stations.html

المتوقع:

  • يظهر اسم الكمبيوتر الحقيقي.
  • الحالة: PENDING / بانتظار الاعتماد.
  • يظهر زر اعتماد الكمبيوتر.

اضغط اعتماد الكمبيوتر.

6. التأكد من ONLINE

بعد الاعتماد، Agent يفحص الحالة دوريًا ثم يرسل Heartbeat.

Agent ↓ status = approved ↓ heartbeat ↓ server updates last_seen_at ↓ MyTool موثوق + ONLINE

يمكن الضغط على تحديث في شاشة المحطات لمشاهدة الحالة فورًا.

7. اختبار OFFLINE

  1. بعد نجاح ONLINE، أوقف Agent بواسطة Ctrl+C.
  2. انتظر أكثر من 90 ثانية.
  3. اضغط تحديث في MyTool.
  4. يجب أن تبقى المحطة موثوقة لكن تصبح OFFLINE.
ONLINE ليست قيمة محفوظة ثابتة. تحسب من approved + last_seen_at حديث.

8. تشغيله مرة أخرى

cd C:\MyTool\station-connect\agent npm start

المطلوب: يستخدم نفس Station UUID ونفس الهوية المحمية، ولا ينشئ Station جديدة.

9. تحديث المشروع لاحقًا من GitHub

أوقف Agent أولًا، ثم:

cd C:\MyTool\station-connect git pull cd agent npm run check npm start
إذا أضفنا Dependencies مستقبلًا، ننفذ npm install بعد git pull.

10. ما لا نفعله الآن

  • لا Windows Service قبل نجاح الاختبار اليدوي.
  • لا ربط مودم.
  • لا HiLink.
  • لا USSD.
  • لا Flexy Job.

بوابة الانتقال هي نجاح:

PENDING ↓ APPROVED ↓ ONLINE ↓ OFFLINE test ↓ نبدأ المرحلة التالية

11. استكشاف الأخطاء

SERVER_URL is requiredملف .env غير موجود أو لا يحتوي SERVER_URL.
Station server is unavailableتحقق من الإنترنت، SERVER_URL، وحالة station-gateway.
Station identity recovery is requiredيوجد installation marker لكن ملف الهوية مفقود/تالف. لا تحذف السجل ولا تنشئ هوية جديدة يدويًا قبل مراجعة الحالة.
بقيت PENDINGافتح MyTool → المحطات واضغط اعتماد الكمبيوتر.
APPROVED لكنه OFFLINEتأكد أن Agent يعمل وابحث في الشاشة عن status: approved ثم heartbeat: ok.

12. قواعد الأمان

  • لا تنشر agent/data/identity.json.
  • لا ترسل Station Secret في رسالة أو Screenshot.
  • لا يخرج MachineGuid الخام من Windows.
  • لا تنسخ هوية Station من كمبيوتر إلى آخر.
  • الكمبيوتر يتصل Outbound فقط؛ لا Port عام على Windows.

بعد نجاح الاختبار

الخطوة التالية بعد نجاح الكمبيوتر الحقيقي ستكون ربط طبقة المودم والـAdapter/HiLink، مع الحفاظ على قاعدة REVIEW عند تغير USB أو Adapter Mapping.

فتح شاشة المحطات الحقيقية ← الكود الذي سنعيد استخدامه للمودم ← مراجعة معمارية السيرفر ←

Station → Modem → SIM

الربط الحالي صار فعليًا داخل Supabase، وليس مجرد توثيق.

Station ↓ Modem - IMEI أولًا - Serial احتياط - HiLink IP ↓ SIM - ICCID إن توفر - IMSI إن توفر - رقم MSISDN من المودم أو يدوي - النوع - PIN مشفّر
PIN تابع للشريحة وليس للمودم. إذا انتقلت شريحة معروفة بـICCID/IMSI إلى مودم آخر، ينتقل نفس سجل الشريحة إلى المودم الجديد.

إدخال رقم الشريحة والـPIN

من إدارة النظام ← المحطات يظهر كل مودم وكل شريحة بعد تشغيل Agent 0.3.0.

الحقلالمصدرالسلوك
IMEI / SerialHiLinkيقرأهما Agent تلقائيًا
ICCID / IMSIHiLink إن توفراهوية ثابتة للشريحة
MSISDNHiLink أو يدوي10 أرقام وUnique، واليدوي لا يستبدل بلا سبب
SIM Typeالإدارةحاليًا SAMA أو Arsselli
PINالإدارةيحفظ في Supabase Vault مشفّرًا
لم يعد هناك SAMA_PIN داخل .env. Agent يأخذ PIN فقط مع Job مصادق عليها عبر HTTPS.
