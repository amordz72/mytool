# مهام معالج البطاقات

آخر تحديث: 2026-08-26

## الحالة الحالية

- [ ] `PENDING` **فصل محتوى الأقسام**: كل تبويب (Mobilis / Token Store / نص عادي) يحتفظ بحالته الخاصة أثناء التنقل: النص الأصلي، النتيجة، التقسيم، واسم الملف. التحميل من أي تبويب يعتمد على محتواه ونتيجته فقط، بدون خلط مع تبويب آخر.
- [ ] `PENDING` **زر مسح المحتوى**: إضافة زر واضح لمسح التبويب الحالي فقط: النص + النتيجة + اسم الملف + حالة التقسيم، بدون تحديث الصفحة كاملة. إذا كان التبويب يحتوي بيانات، يعرض تأكيدًا قبل المسح.
- [ ] `PENDING` **عدم تعديل النص الأصلي عند Trim**: النص الملصق أو المرفوع يبقى محفوظًا حرفيًا كما هو. خيار Trim يعمل فقط على نسخة المعالجة/المخرج، ولا يكتب فوق النص الأصلي ولا يغيره داخل مربع النص.
- [ ] `PENDING` **توضيح معنى خيار Trim في الواجهة**: تعديل تسمية الخيار ليكون واضحًا أنه يؤثر على المخرج فقط، مثل: «إزالة الفراغات من المخرج فقط».
- [ ] `PROPOSED` **حفظ مؤقت للنص الأصلي بعد تحديث الصفحة**: لم يُحسم بعد. إن تم اعتماده، يفضّل Session Storage أو آلية جلسة مؤقتة، وليس حفظًا دائمًا، خصوصًا مع أكواد البطاقات.

## تحسينات قابلة لإعادة الاستخدام لاحقًا

- [ ] `PROPOSED` علامة على التبويب الذي يحتوي عملًا محفوظًا، مع عدد العناصر إن أمكن.
- [ ] `PROPOSED` إبقاء النتيجة وحالة التقسيم كما هي عند الانتقال بين التبويبات.
- [ ] `PROPOSED` زر «إعادة المعالجة» يستعمل النص الأصلي الحالي بدون إعادة لصقه.
- [ ] `PROPOSED` إمكانية Undo قصيرة بعد مسح المحتوى، إذا كانت بسيطة ولا تعقّد الواجهة.
- [ ] `PROPOSED` ملخص تحقق للمصادر المنظمة مثل Token Store: عدد الأقسام / عدد المنتجات / عدد الأكواد / عدد المستخرج / الحالة.

## قاعدة مهمة

المصدر الأصلي = Raw Source، ويجب اعتباره للقراءة فقط أثناء المعالجة.
أي Trim أو Normalize أو استخراج أو تنظيف يتم على نسخة مشتقة داخل المعالج. لا يغيّر المصدر الأصلي إلا بفعل صريح من المستخدم.

لا تعتبر أي مهمة منجزة حتى تكون موجودة فعلًا في الكود، وبعدها تُغيّر حالتها إلى `IMPLEMENTED`، وبعد اختبارها عمليًا إلى `TESTED`.
