# سجل حساب المحل — MyTool

الحالة: `IN PROGRESS`

## الهدف
إضافة خدمة بسيطة داخل MyTool لتسجيل حركات المحل القادمة من مجموعة الخدام، ثم استعمالها لاحقًا في الجرد.

## المطلوب مبدئيًا
- تسجيل كل حركة مع: التاريخ، الوقت، العامل/الشخص، الصنف أو الوصف، المبلغ، ونوع العملية.
- تجميع حساب كل شخص على حدة وعرض إجماليه.
- إظهار الإجمالي العام للفترة.
- في مرحلة لاحقة ربط هذه الحركات مع جرد/إغلاق الصندوق والمخزون.

## التخزين
تم اعتماد **Supabase / PostgreSQL** كقاعدة البيانات الأونلاين للمشروع بدل حفظ البيانات التشغيلية داخل GitHub.

الجداول الحالية:
- `staff`
- `products`
- `purchases`
- `sales`
- `stock_adjustments`

وعرض الجرد المحسوب:
- `inventory_summary`

الجرد يُحسب من المشتريات والمبيعات وتصحيحات المخزون، ولا يُخزن كرقم مستقل قابل للتعارض مع سجل العمليات.

## الربط الحالي
تم إنشاء واجهة أولية داخل `shop/index.html` مرتبطة مباشرة بـ Supabase باستخدام:
- Vue 3 من المتصفح بدون build في المرحلة الحالية.
- `@supabase/supabase-js` من المتصفح.
- Project URL + Publishable key فقط.
- تسجيل الدخول عبر Supabase Auth.
- قراءة `staff` و`products` و`inventory_summary`.
- تسجيل المبيعات في `sales`.
- تحديث المخزون بعد كل عملية.

تمت إضافة مدخل **حساب المحل** إلى الصفحة الرئيسية لـ MyTool.

هذا الأسلوب مقصود ليبقى MyTool بسيطًا الآن، مع إمكانية نقله لاحقًا إلى Vue/Vite كامل بدون تغيير قاعدة البيانات.

## المنتجات والمخزون والجرد الفعلي
الحالة: `IMPLEMENTED` — يحتاج اختبارًا عمليًا بعد النشر.

تم توحيد إدارة المخزون داخل قسم **المنتجات والمخزون** بثلاثة أوضاع للإدارة:
- **المنتجات:** إضافة منتج وتعديل اسمه مع الحفاظ على سجل الحركات القديمة.
- **المخزون:** عرض الكمية الحالية المحسوبة من الحركات.
- **الجرد الفعلي:** إدخال العدد الحقيقي للسلع التي تم عدها فقط، إظهار الفرق موجبًا أو سالبًا، ثم تسجيل الفرق كحركة مستقلة في `stock_adjustments` مع السبب بدل تعديل أو حذف المبيعات القديمة.

واجهة الجرد لا تفترض اسم عمود كمية التعديل؛ تتحقق وقت التنفيذ من أسماء الحقول المعروفة في جدول `stock_adjustments` قبل الحفظ، وتتوقف برسالة واضحة إذا لم تتعرف على البنية بدل كتابة بيانات خاطئة.

فروق الجرد المتعددة تُرسل في عملية إدخال واحدة حتى لا يُحفظ جزء من الجرد ويُرفض جزء آخر.

تم استعمال كمية تجريبية مبدئية موحدة أثناء الإعداد فقط، وليست جردًا حقيقيًا للمحل.

## الحماية
- RLS مفعّل على الجداول التشغيلية.
- الوصول الحالي مخصص للمستخدمين المسجلين `authenticated` فقط.
- التسجيل العام للمستخدمين الجدد معطل؛ الحسابات تُنشأ يدويًا من الإدارة.
- تسجيل الدخول المجهول معطل.
- لا يُستخدم `service_role` أو أي Secret key في الواجهة أو في GitHub.
- Publishable key مفتاح عميل عام، والحماية الفعلية تعتمد على Auth + RLS.

## سياسة البيانات
لا تضع داخل مستودع GitHub العام:
- كلمات المرور.
- مفاتيح `service_role` أو Secret keys.
- أرقام الهواتف أو بيانات الزبائن الحساسة.
- المبيعات والمخزون والمبالغ الفعلية كملفات ثابتة.

البيانات الحقيقية تبقى في Supabase، والنسخ الاحتياطية الحساسة خارج GitHub العام.

## الخطوة التالية
اختبار صفحة `shop/` من الهاتف:
1. تسجيل الدخول بالحساب الذي تم إنشاؤه يدويًا.
2. التأكد من ظهور السلع والمخزون.
3. تسجيل عملية بيع تجريبية واحدة والتأكد من نقص المخزون.
4. اختبار تبويبات **المنتجات / المخزون / الجرد الفعلي** وتسجيل فرق جرد تجريبي واحد.

ابدأ بأبسط نسخة عملية ولا تحوّل المرحلة الأولى إلى نظام محاسبة كامل.
